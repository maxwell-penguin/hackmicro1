MigraLoop

Schema drift is inevitable.
Silent data loss shouldn't be.

Production database schemas drift from ORM models over time. Asking an LLM to "just generate a fix" often makes it worse: a single-shot model frequently resolves a rename or type change by dropping the column and recreating it. Syntactically fine, semantically catastrophic. MigraLoop puts a deterministic, non-AI Data Loss Guardian between "the agent wrote a migration" and "the migration is accepted."

Built on SQLite (not Postgres) for a disposable, Docker-free sandbox and reproducibility on a judge's machine. See README.md's Scoping Notes for why.

Architecture

Five stages, one non-negotiable gate

01
State Extractor
Deterministic schema diff. No LLM.
02
Migration Synthesizer
LLM call. Forces a declared drop manifest.
03
Sandbox Verifier
Applies the migration to an isolated SQLite copy.
04
Data Loss Guardian
Deterministic. Rejects undeclared data loss.
05
Retry loop
Retries with a fresh sandbox, up to 3x.
