# Reproduction

Exact steps to run MigraLoop from a clean clone.

## 1. Clone and enter the repo

```bash
git clone <repo-url> hackmicro1
cd hackmicro1
```

## 2. Install dependencies

```bash
python -m pip install -r requirements.txt
```

Use `python -m pip`, not a bare `pip install`. `pip` on your `PATH` can
resolve to a different Python interpreter than the one `python`/`make`
will actually run (common with multiple Python versions or a stray global
install) — `python -m pip` guarantees the package lands in the same
interpreter that runs the rest of these commands.

## 3. Set up the benchmark databases

```bash
python benchmarks/setup_benchmarks.py
```

This builds the `physical.db` SQLite files under `benchmarks/*/` that the
baseline and advanced runs both read from.

## 4. Set your API key

```bash
cp .env.example .env
```

Edit `.env` and fill in `ANTHROPIC_API_KEY` with your own key (`.env` is
gitignored and never committed). See `.env.example` for the optional
`MIGRALOOP_MODEL` override.

## 5. Run the benchmark suite

```bash
make baseline   # single-shot LLM, no Guardian/retry loop
make advanced   # full MigraLoop: extractor + synthesizer + sandbox + guardian + retry
make evaluate   # diffs baseline vs. advanced, writes results/comparison.md
make test       # unit tests (no API key required)
```

`make baseline` and `make advanced` call the Anthropic API for every
benchmark case and will make real, billed API calls — they require a live
`ANTHROPIC_API_KEY` in `.env`. `make test` and `make evaluate` do not call
the API.

## 6. Generate the demo page

```bash
make demo
```

Reads the committed `results/` and `trajectories/` output plus README.md's
Hot Take section and writes `demo/data.js`. Then open `demo/index.html`
directly in a browser — it's a static page with no server and no API calls;
it only replays the captured evaluation run. Re-run `make demo` any time
`results/`, `trajectories/`, or README.md's Hot Take section changes, so the
page can't drift out of sync with the real evidence.

## 7. Run the local web UI (upload your own database)

```bash
make web
```

Starts a local-only FastAPI server at http://localhost:8000 — no auth, no
rate limiting, not meant to be exposed beyond your own machine. Open that
URL, upload a `.db`/`.sqlite` file (the physical/drifted database) and paste
the target schema SQL, then click "Run MigraLoop". It calls the same
`src/orchestrator.run_case()` used by `make advanced`, with a real
`MigrationSynthesizer()` — a real, billed Anthropic API call — and shows the
drift report, synthesized migration SQL, and Guardian verdict once it
finishes (typically 10-30s). Requires `ANTHROPIC_API_KEY` in `.env` (step 4).

You can try it against a known-good case, e.g. `benchmarks/02_rename_column_with_data/`:
upload its `physical.db` and paste the contents of its `target_schema.sql`.

## 8. Where to find the output

- `results/baseline_results.json`, `results/advanced_results.json` — per-case
  structured outcomes (success/error, data-loss detection, attempt counts).
- `results/comparison.md` — the baseline-vs-advanced table generated by
  `make evaluate`.
- `trajectories/baseline/*.json`, `trajectories/advanced/*.json` — full
  step-by-step agent trajectories (one file per case) showing every
  reasoning/tool-call/error step in the run.

`make clean` removes all of the above plus the generated `physical.db`
files, if you want to start over.
